Keyboard navigation

Keyboard users move with Tab / Shift+Tab and activate with Enter or Space. What can receive focus depends on semantics and tabindex — “focusable” and “tabbable” are not the same thing.

Tabbable vs focusable

Plain text is neither in the tab order nor programmatically focusable. tabindex="-1" allows element.focus() (and skip targets) without adding the element to the Tab sequence. tabindex="0" puts a non-interactive element in the natural tab order — use sparingly, and only when it must be keyboard-operable.

Positive tabindex reorders focus

Positive values put those elements first in the page’s Tab sequence, sorted by number — before anything with 0 or no tabindex. That almost always fights the visual order. Prefer source order (and CSS for layout) instead of tabindex="1"+.

Click handlers need a real control

A div with only a click handler is mouse-friendly and keyboard-hostile: it is not focusable, and Enter / Space do nothing. Native button and links with href already participate in the tab order and expose the right activation keys.

Focus outlines

Tab through these buttons. Removing the outline (0, none, or transparent) hides keyboard focus unless you replace it. Prefer a visible custom outline — optionally with offset, a second ring, or currentColor so it tracks the control’s text color.

:focus, :focus-visible, and :focus-within

:focus styles appear for mouse and keyboard. :focus-visible targets keyboard (and other non-pointer) focus. :focus-within styles an ancestor while a descendant has focus — useful for cards and field groups.
