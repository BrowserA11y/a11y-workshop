Live regions

Live regions tell assistive technologies about content that changes without a focus move. Prefer semantic roles like status, alert, and <output> when they fit; use aria-live when you need finer control.

Native <output>

The output element is an implicit live region (role="status"). Associate it with a label via for/id.

0

aria-live and aria-atomic

Without aria-atomic, many screen readers announce only what changed (often just the number). With aria-atomic="true", the whole region is re-read — e.g. “9 seconds left”. Prefer aria-live here: role="timer" is not supported in Chrome.

aria-relevant additions and removals

The default for aria-relevant is additions text. Setting aria-relevant="additions removals" also announces removals. Use each list’s controls separately to compare.

      Plain text only

      Live regions announce text content — they do not communicate semantic roles. A heading or button inside a live update is usually read as plain words, not as “heading” or “button”. Keep live messages as plain text; leave real structure and controls in the page outside the live region.

      Heading and button inside live region

      Plain text message

      Live region must exist before the update

      Assistive technologies watch live regions that are already in the render tree. If a disclosed widget inserts a live region that already contains text, the change is often never announced. Keep the live region mounted (even when empty), then update its text after it is present.

      Skeletons and aria-busy

      A visual skeleton alone is not an accessible status. Pair loading UI with aria-busy="true" on the container being updated so assistive technologies know content is in flux.

      Offscreen live announcer

      An imperative announcer updates a visually hidden live region when there is no suitable live region in the DOM — for example after a save that only shows a toast visually. (Angular CDK exposes this as LiveAnnouncer.)

      Deferred content inside a polite live region

      Wrapping deferred UI in aria-live="polite" with aria-atomic="true" can announce placeholder, loading, and loaded content as the block swaps. Trigger the load, then listen with a screen reader. (In Angular this uses @defer; here we use setTimeout.)
