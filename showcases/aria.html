ARIA

ARIA can expose roles and states that HTML alone does not — but it does not add behavior, and unknown or conflicting markup is often ignored or harmful. Prefer native elements; use ARIA when you cannot.

Implicit ARIA roles

Many HTML elements already map to ARIA roles in the accessibility tree. You do not need to add role — the browser supplies it from the element type.

ARIA roles

Explicit roles change how assistive technologies announce an element. Valid roles from the ARIA vocabulary are exposed; invented names are ignored. Roles do not add keyboard support or click handling — wire that yourself when you leave native controls behind.

aria-hidden

aria-hidden="true" removes a subtree from the accessibility tree. Use it for decorative visuals — never on focusable or meaningful content that keyboard users can still reach.

aria-live

Live regions announce changes without moving focus. aria-live="polite" waits for a pause; assertive interrupts. Prefer built-in roles like status / alert when they fit.
